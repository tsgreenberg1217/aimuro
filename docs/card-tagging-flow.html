From card text to rule pointers

What happens to each card between findCard and the <facts> block. Every step is deterministic code driven by one fixed tag table. Nothing here depends on the question except the final mechanics filter.

Question-independent until the filter

Everything above the mechanics filter depends only on the card, so a CardAnnotation can be cached by card code and reused across questions.

Reminder text is dropped

Parenthesized keyword explanations have no game effect (rule 2-11-4). Stripping them keeps the clause body to what the card actually does, and the full rule comes from the tree instead.

Fail-open, never silent

An untagged clause or an unknown tag stays in the facts as plain text, so the model can still send it to answerRulesQuestion. Unknown tags also log a warning, so a new card set shows up as missing table rows.

Link is parsed, not judged

The link field becomes a typed condition here. Whether a given pilot satisfies it is decided later by the checkLink tool, only when the model asks.
